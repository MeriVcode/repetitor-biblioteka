БЕСПЛАТНАЯ БИБЛИОТЕКА М. БРАТУХИНОЙ
Готовый сайт для GitHub Pages

ЧТО НАХОДИТСЯ В АРХИВЕ
- index.html — главная страница библиотеки.
- editor.html — редактор карточек и каталога.
- catalog-data.js — карточки опубликованных материалов.
- app.js / editor.js / styles.css — логика и оформление.
- assets/ — художественное оформление и изображения карточек.
- materials/ — сами HTML-материалы.

На старте в каталоге включена ТОЛЬКО «Лингвистическая почта».
Она открывается из локальной папки materials/lingvisticheskaya_pochta.html.
Исходные файлы некоторых других ранее созданных материалов в этот комплект не вошли,
потому что их доступные для публикации копии/ссылки не удалось подтвердить.
Неработающие карточки не добавлялись.

КАК ОТКРЫТЬ ДЛЯ ПРОВЕРКИ
1. Распакуйте ZIP в одну папку.
2. Дважды щёлкните index.html.
3. Нажмите «Открыть» у «Лингвистическая почта»: материал должен открыться в новой вкладке.
4. Для проверки редактора откройте editor.html.

КАК РАЗМЕСТИТЬ НА GITHUB PAGES
1. Войдите в github.com, нажмите New repository.
2. Придумайте имя, например biblioteka-repetitora, выберите Public.
3. Загрузите ВЕСЬ набор файлов, сохранив папки assets/ и materials/.
   Важно: index.html должен быть в КОРНЕ репозитория.
4. Откройте Settings → Pages → Build and deployment.
5. Source: Deploy from a branch. Branch: main, folder: /(root). Нажмите Save.
6. После публикации GitHub Pages сайт будет доступен по адресу
   https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/
   (адрес — шаблон; фактическую ссылку смотрите в Settings → Pages).
7. Разместите РЕАЛЬНЫЙ полученный адрес библиотеки в сообществе ВКонтакте.

КАК ДОБАВИТЬ НОВЫЙ МАТЕРИАЛ, НЕ ИЗМЕНЯЯ КОД САЙТА
1. Убедитесь, что у вас уже есть рабочий HTML-файл или ссылка на опубликованный материал.
2. Если HTML хранится в этом репозитории, загрузите его в папку materials/ на GitHub.
   Например, materials/moya_igra.html. Для страницы PDF используйте аналогичный путь.
3. Откройте https://ВАШ_САЙТ/editor.html (или локальный editor.html).
4. Нажмите «+ Новая карточка» и заполните название, раздел, предмет, тип,
   классы, описание, время работы (по желанию) и путь materials/moya_igra.html
   либо настоящую ссылку https://...
5. Загрузите изображение через поле «Изображение карточки».
   Редактор уменьшает картинку и встраивает её в данные — отдельно загружать не надо.
6. Нажмите «Сохранить карточку», потом «Посмотреть черновик».
7. Нажмите «Скачать обновлённый каталог».
8. На GitHub откройте репозиторий и загрузите скачанный catalog-data.js
   в КОРЕНЬ сайта с заменой предыдущего файла. Нажмите Commit changes.
9. После публикации обновите страницу с очисткой кеша (Ctrl+F5).

ВАЖНО: «Сохранить карточку» сохраняет только локальный черновик браузера!
ОПУБЛИКОВАТЬ изменения для всех посетителей можно лишь заменив catalog-data.js
в GitHub. Редактор НЕ имеет доступа к вашему аккаунту GitHub и не публикует сам.
Если новый материал будет на другом сайте, добавьте только его РЕАЛЬНЫЙ URL.
Если изображения нет, карточка показывает иллюстрацию раздела.

КАК ИСПРАВИТЬ ИЛИ УДАЛИТЬ КАРТОЧКУ
1. Откройте editor.html.
2. Выберите карточку слева.
3. Измените поля или нажмите «Удалить карточку».
4. Скачайте новый catalog-data.js и замените его в репозитории.

КАК СДЕЛАТЬ РЕЗЕРВНУЮ КОПИЮ
Сохраняйте исходный ZIP и каждую последнюю версию catalog-data.js.
Текущий список карточек — это именно содержимое этого файла.

ОТЛИЧИЕ «РАЗДЕЛА» ОТ «ПРЕДМЕТА»
Раздел определяет полку, где появится карточка (математика, русский язык,
чтение, онлайн-доски, конструкторы, диагностика).
Предмет обозначает содержание — например, онлайн-доска по русскому языку.
Читатели могут фильтровать по обоим параметрам независимо.

КАК ПРОВЕРИТЬ ССЫЛКУ
После загрузки на GitHub нажмите «Открыть» в каталоге. Если браузер покажет
404, проверьте имя HTML-файла и путь в каталоге (регистр букв важен).

Статус: браузерная проверка отображения, фильтров, поиска, редактора, экспорта
и адаптивности проведена в Chromium. Путь кнопки «Открыть» проверен по наличию
реального HTML в папке materials/. Прямой переход на этот HTML из сайта и
реальная публикация на вашем GitHub Pages в этой среде не проверялись.
